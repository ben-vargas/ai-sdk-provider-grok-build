# Normalize, redact, and strictly validate transport events

ACP and headless records are normalized into generation-neutral text, reasoning, tool, usage, finish, metadata, and raw-event shapes before an AI SDK adapter sees them. Raw events, tool data, usage, model catalogs, and extension metadata are credential-redacted. Unknown optional events are preserved with one compatibility warning, but semantic event-name tokens in the tool, permission, usage, completion, finish, and end families fail closed because they could alter stream correctness; observed benign names such as `auto_compact_completed` remain explicitly allowed instead of relying on broad substring exceptions.

Completion requires authoritative terminal data, and tool updates must correlate to the real originating tool identity. Duplicate tool-call IDs are rejected before correlation state is mutated. Before a final result, a status-less `tool_call_update` is non-final progress and cannot complete its tool call. After a final result, status-less metadata updates are ignored semantically, duplicate terminal updates are accepted idempotently, and pending or in-progress regressions fail as protocol errors. A documented top-level `{ type: "error", message }` record is terminal and retains its message; nested or nonfatal error shapes are not inferred without observed protocol evidence. Malformed required records, missing terminal data, and unresolved tool calls fail explicitly.

ACP response-state validation is a separate client-boundary contract rather than an event-normalization responsibility. Wire fields with protocol-defined defaults are normalized when omitted or encoded as `null`: initialize authentication methods become `[]`; record capabilities become `{}`; boolean capabilities become `false`; and a null authenticate result becomes `{}`. Malformed non-null strings, arrays, objects, and leaf values remain errors. Reasoning efforts require a non-empty `value`; omitted `id` and `label` normalize to that value, while invalid supplied fields remain errors. Prompt results must be non-null objects with a non-empty `stopReason` and valid optional metadata.

Both validation paths retain credential redaction so malformed wire data produces an `AcpProtocolError` rather than leaking raw payloads or surfacing incidental JavaScript type errors. Newline-terminated malformed JSON remains an `AcpProtocolError` with exit and stderr context, as does an unterminated record discovered on a clean exit. When a nonzero or signalled exit truncates the final JSON record, the more authoritative result is `AcpProcessExitError` with complete stderr and the parse failure preserved as its cause; only records emitted by the framer's EOF flush receive this treatment.
