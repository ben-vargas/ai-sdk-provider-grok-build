# Target Grok CLI 1.x behind an explicit binary trust boundary

The provider supports Grok CLI `>=1.0.0`, disables automatic updates on built-in launch paths, and performs a bounded cached version check rather than carrying compatibility behavior for older CLIs. Resolution prefers `executablePath`, then a package binary rooted at `cwd` only when `allowPackageBin` explicitly trusts that directory, then `PATH`, and finally an explicitly enabled `npx` fallback. Package discovery is off by default because repository-controlled code would inherit credentials during the version check; the compatibility-breaking default is recorded under Unreleased for the next minor release rather than changing the current package version.

Version collection waits for child-process `close`, uses an independent 30-second default bound, and lets each caller abort its own wait without cancelling or poisoning a shared cached check. Provider `timeouts.requestMs` remains specific to ACP JSON-RPC requests and is not part of the version-check identity, so models with different request bounds share the same check; low-level callers may still opt into a different version bound with `GrokVersionCheckOptions.timeoutMs`.

Windows accepts only native executables through `PATH` or `executablePath`: PATH lookup skips `.cmd` and `.bat` shims and keeps searching, explicit script paths remain typed errors, and package and `npx` fallbacks stay disabled rather than introducing shell execution. Grok remains consumer-managed rather than a package dependency so applications retain control over binary selection, installation, and upgrades.

A custom `GrokBuildLanguageModel` `clientFactory` is an explicit command-line ownership boundary. It receives no generated `args` by default and is responsible for its complete launcher contract, including binary resolution, version validation, update suppression, and permission flags. A real-CLI custom factory may opt into the built-in resolution, version gate, and generated arguments with `validateCli: true`; default construction and the internal pooled provider enable that path automatically.
